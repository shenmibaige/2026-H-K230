## 🎯 项目简介

本仓库是 **2026 年大学生电子设计竞赛 · 辽宁赛区 H 题「车载平衡滚球运动控制系统」** 的完整开源实现：一辆沿黑色循迹线行驶的小车，车上由舵机驱动的摆球机构负责让钢珠在导轨中稳定停在指定位置。

系统由两块板子构成：

| 角色 | 平台 | 职责 |
| --- | --- | --- |
| **控制核心** | TI **MSPM0G3507**（CCS 工程，裸机 + 1 ms 定时器节拍） | 灰度循迹、编码器测速、双电机 PID、舵机摆球控制、OLED 菜单、按键交互 |
| **视觉核心** | Canaan **K230**（CanMV / MicroPython） | 自训练 YOLO 类检测模型定位钢珠，输出横向偏差 `dx`，并通过串口下发给主控；同时提供 720P RTSP 图传 |

> 💡 **亮点**：视觉侧在**单颗 K230 上同时跑三路 Sensor 通道**——CH0 供 LCD 显示、CH1 硬编 H.264 推 RTSP 图传、CH2 供 AI 推理，图传失败时自动降级、不影响识别与串口闭环。

## 🧠 系统架构

```text
                    ┌──────────────── K230 (CanMV / MicroPython) ────────────────┐
                    │  Sensor CH0 ──▶ LCD 显示（ST7701 / LT9611）                 │
                    │  Sensor CH1 ──▶ VENC 720P H.264 ──▶ RTSP :8554/ball        │
                    │  Sensor CH2 ──▶ 320×320 AnchorBaseDet 推理 ──▶ dx 偏差      │
                    └───────────────────────────┬────────────────────────────────┘
                                                │ UART 115200  "@<dx>\r\n"
                                                ▼
   ┌──────────────────────────── MSPM0G3507 (CCS / 裸机) ────────────────────────────┐
   │  UART0 RX(PA31) ──▶ 邮箱取最新帧 ──▶ 位置/速度估计 ──▶ 分段 PID ──▶ 舵机 PWM(PA27) │
   │                                       ▲                          │              │
   │  灰度传感器 ──▶ 循迹控制律 ──▶ 电机 PWM ──▶ 编码器测速 ──┘         │ 摆球机构      │
   │                                      OLED 菜单 / K1 K2 按键 ◀─────┘              │
   └────────────────────────────────────────────────────────────────────────────────┘
```

- **控制节拍**：`TIMER_PID_INST` 每 **1 ms** 触发一次，统一驱动系统计时、按键扫描与当前模式的 `ModeXX_Tick1ms()`。
- **闭环关系**：循迹环（灰度 + 编码器 → 电机）与滚球环（K230 `dx` → 舵机）独立运行，互不阻塞。

## 👁 视觉子系统

训练与部署链路：`YOLO 类检测模型 → nncase 2.9.0 量化 → .kmodel → K230 AI 通道推理`。

| 项目 | 值 |
| --- | --- |
| 模型类型 | `AnchorBaseDet`（单类别：`ball`） |
| 部署文件 | `best_AnchorBaseDet_can2_5_n_20260730052458.kmodel` |
| 推理尺寸 | 320 × 320（int8 PTQ，`w:uint8 d:uint8`，NoClip 标定） |
| 置信度 / NMS 阈值 | 0.5 / 0.5 |
| AI 通道 | CH2，RGB888 Planar，中心 X = 540 px |
| 图传 | CH1，1920×1080@30 采集 → 1280×720@30 H.264 Main，4000 kb/s，GOP 30 |
| 图传地址 | `rtsp://<K230 的 IP>:8554/ball`（脚本启动后打印 `RTSP_READY=`） |

**偏差计算与滤波**（`08 2026电赛小车视觉.py`）：

1. 取面积最大的检测框中心 `ax`，`raw_dx = ax - CENTER_X_AI`（右为正、左为负）；
2. **跳变保护**：若 `|raw_dx - filtered_dx| > 300 px`，需连续 10 帧且帧间波动 ≤ 300 px 才接受，否则丢弃；
3. **一阶低通**：`filtered_dx = 0.7 × filtered_dx + 0.3 × raw_dx`；
4. 检测不到钢珠时下发丢失标志 `LOST_DX = -999`；
5. 同时把 `dx`、中心线、FPS 画到 OSD 上，便于现场对位。

**部署方法**：把 `mp_deployment_source/` 整个目录拷进 K230 的 SD 卡，运行 `08 2026电赛小车视觉.py` 即可（详见 `视觉使用方法.txt`）。

## 📡 通信协议

K230 每帧推理结果通过 UART 以 ASCII 帧下发，主控侧不阻塞地取最新一帧：

```text
主控接收：  '@' + <dx 十进制字符串> + "\r\n"      例：@-137\r\n
            dx 单位：像素（约 45 px/cm）；-999 表示本帧未检测到钢珠
主控发送：  仅诊断信息，不参与闭环
```

主控侧由 `driver/uart.h` 提供：

| 接口 | 作用 |
| --- | --- |
| `UART_TakeLatestPacket()` | **原子地**取走最新完整帧，同时返回中断里记录的时间戳与最大帧间隔 |
| `UART_ResetRxMailbox()` | 每次启动任务前清空邮箱，丢弃上一轮残留数据 |
| `UART_RxOverwriteCount` | 统计被覆盖的帧数，用于评估 OLED 等前台任务是否影响实时性 |

> 设计要点：时间戳在 **UART 中断内**记录，而非主循环唤醒时；配合 `BALL_VISION_TIMEOUT_MS = 80 ms`，一旦视觉断流立即进入安全策略。

## 🧩 PID 多维参数调度（核心设计）

**动机**：舵机打角驱动钢珠是典型的**双积分型对象**（舵机倾角 → 钢珠加速度 → 速度 → 位置），
单一固定 PID 无法同时满足两个相互矛盾的诉求——**大偏差时要"快"**（快速回中不磨蹭），
**小偏差时要"稳"**（不振荡、不超调、能压住稳态误差）。

所以本工程没有用一组 PID 打天下，而是**把 PID 参数当作被控状态的函数**，
在 **5 个维度**上实时调度参数，每个维度对应一类明确的物理情形。

| 维度 | 调度依据 | 实现位置 |
| :---: | --- | --- |
| ① 误差幅值 | `\|dx\|` 分段 → S1…S6 变增益表 | `mode_q4.c` / `mode_q5.c` |
| ② 误差区域 | 相邻区域**线性插值软切换**，6 组独立 PID 并行 | `ball_pid_bank.c` |
| ③ 任务阶段 | 状态机所处阶段（驱动 / 制动 / 接近 / 稳定 / 保持） | `ball_controller.c` |
| ④ 保持区内外 | `\|dx\| ≷ 45 px(≈1 cm)` 附加增益与微分强度 | `mode_q5.c` |
| ⑤ 目标方向 | A 点（+5 cm）与 B 点（−5 cm）各自独立成组 | `ball_config.h` |

> 📌 **两套调度机制的实际归属**——仓库里其实有两次独立实现，思路同源但落点不同：
>
> | 模式 | 走的路线 | 核心文件 |
> | :---: | --- | --- |
> | `Q3` | 维度 ②③⑤：状态机 + 6 组 PID 软切换 | `ball_controller.c`、`ball_pid_bank.c` |
> | `Q4` / `Q6` | 维度 ①④：S1–S6 分段表 + 保持区内外增益 | `mode_q4.c`、`mode_q5.c` |
>
> 两者都是"参数随工况变化"，只是 `Q4`/`Q6` 用**分段直接取值**（实现简单、便于现场手调），
> `Q3` 用**加权融合**（过渡连续、适合 B 点这种要求定点精度的场景）。如需统一，建议以软切换方案为基准。

### 维度一：按误差幅值的分段增益（S1–S6）

偏差越大 → 越激进地往回打；偏差越小 → 越保守地精细保持。
这是最直观的一维，也是整套调度机制的骨架。

| 段 | `\|effectiveDx\|` 上限 | Kp | Ki | Kd | 输出限幅 | 斜率限幅 |
| :---: | :---: | :---: | :---: | :---: | :---: | :---: |
| `S1` | ≤ 10 px | 0.020 | 0.0012 | 1.4 | 8° | 1.0° |
| `S2` | ≤ 30 px | 0.028 | 0.0008 | 1.3 | 12° | 1.5° |
| `S3` | ≤ 45 px | 0.035 | 0.0005 | 1.2 | 20° | 2.5° |
| `S4` | ≤ 100 px | 0.045 | 0.0003 | 1.1 | 35° | 4.0° |
| `S5` | ≤ 160 px | 0.055 | 0 | 1.0 | 45° | 6.0° |
| `S6` | > 160 px | 0.070 | 0 | 1.0 | 55° | 8.0° |

> 数值取自 `mode_q5.c` 的 `Ball_PidStages[6]`。`mode_q4.c` 同一套增益，仅 `S3` 边界放宽到 60 px。

**规律**（这是分段调度的核心思想）：

| 变化方向 | Kp | Ki | Kd | 输出限幅 | 斜率限幅 |
| --- | :---: | :---: | :---: | :---: | :---: |
| 偏差 **变大** | ⬆️ 0.020→0.070 | ⬇️→**0** | ⬇️ | ⬆️ 8°→55° | ⬆️ 1.0°→8.0° |
| 偏差 **变小** | ⬇️ | ⬆️ | ⬆️ | ⬇️ | ⬇️ |

- **大偏差**：高 Kp 抢时间，**Ki 直接归零**避免积分饱和造成过冲，降低 Kd（此时不需要预测阻尼）；
- **小偏差**：低 Kp 防振荡，**高 Ki 消除稳态误差**（钢珠停在目标点），高 Kd 提供阻尼抑制超调；
- **斜率限幅 `OutputDeltaMax` 同步缩放**（1.0° → 8.0°）：小偏差时舵机动作柔和，大偏差时允许快速摆角。

### 维度二：误差区域软切换（6 组 PID 并行 + 权重插值）

`ball_pid_bank.c` 把误差轴划成 6 个区域，**每个区域拥有一套完整的 PID 状态**，
但切换方式不是 `if-else` 硬跳变，而是**连续插值**：

| lane | 区域上界 `error_max_cm` | 混合半宽 `blend_half_width_cm` | Kp (°/cm) | Ki (°/cm·s) | Kd (°/cm·s) | 输出限幅 |
| :---: | :---: | :---: | :---: | :---: | :---: | :---: |
| 1 | 0.17 | ±0.12 | 4.0 | 0.80 | 1.9 | 20° |
| 2 | 0.50 | ±0.15 | 5.0 | 0.50 | 1.7 | 22° |
| 3 | 1.00 | ±0.20 | 6.5 | 0.25 | 1.5 | 24° |
| 4 | 1.67 | ±0.25 | 8.0 | 0.10 | 1.4 | 28° |
| 5 | 2.67 | ±0.35 | 9.5 | 0.05 | 1.2 | 32° |
| 6 | ∞ | — | 11.0 | 0.02 | 1.0 | 35° |

**工作流程**（每 1 ms 执行一次）：

```text
1. 用真实 M0 时间算 dt，超限则清零所有积分（防异常 dt 污染）
2. 误差输入用「预测误差」而非当前误差：
      predicted_error = target − (position + 0.10 s × velocity)   ← 前馈，抵消滞后
3. BallPid_AssignWeights()：按 |predicted_error| 定位区域
      · 落在区域的纯区间  → 该 lane 权重 = 1.0
      · 落在混合带内      → 相邻两 lane 权重 = (1−blend, blend)，线性插值
4. 6 条 lane 全部独立更新：各自积分、各自输出限幅、条件积分抗饱和
5. 融合输出 = Σ(lane[i].weight × lane[i].output_deg)，再限幅 ±35°
```

**为什么要这样设计：**

- **软切换消除抖振**——真实系统的误差总在边界附近抖动，硬切换会导致增益突跳、舵机"打摆"；线性插值让参数随误差**连续变化**；
- **每条 lane 保留独立积分状态**——避免切换瞬间积分量被另一套参数"继承"造成的输出跳变；
  （注释中明确对比了参考实现：旧版是"一个 PID + 6 组增益直接替换"，v3.1 改为"6 个独立状态 + 真实时间 + 加权融合"）
- **条件积分抗饱和**——仅当输出未饱和、或积分方向能把输出拉回范围内时才累积积分；
- **每 lane 独立限幅后再融合**，最后整体再夹一次，保证任何情况下舵机指令都是有界的。

### 维度三：任务阶段的专属控制律

`ball_controller.c` 是一个 13 状态的状态机，**不同阶段根本不用同一套控制逻辑**，
而是各阶段"换一套参数 + 换一种控制手段"：

| 阶段 | 控制手段 | 关键参数 |
| --- | --- | --- |
| `DRIVE_A` / `DRIVE_B` | 固定偏置驱动 + 起步助推 | `BALL_DRIVE_A_OFFSET_DEG = 30°`，助推 `35°` 延迟 160 ms |
| `BRAKE_A` / `BRAKE_B` | **提前制动**（lead 预测 + 反向偏置） | `BALL_BRAKE_A_LEAD_S = 0.22 s`，反向 `−28°`，触发点 4.45 cm |
| `B_APPROACH` | 包络限速 + 预减速 / 二次驱动 | 减速度 `24 cm/s²`，速度包络 2.0–11.0 cm/s，预制动 `22°` |
| `B_SETTLE` | PD 阻尼 + 脉冲微调 + 能量管理 | `Kp = 4.0 °/cm`，`Kv = 1.2 °/(cm/s)`，阻尼基值 `20°` |
| `QUIET`（静稳保持） | 迟滞带 + 偏置脉冲观测 | 进入门限 0.70 cm / 0.35 cm·s⁻¹，退出迟滞 0.75 cm，脉冲 40 ms |

> 例如 `B_SETTLE` 阶段注释里明确写着**能量管理约束**：在阻尼带内，自动指令只允许"滑行"或"反向制动"，**不允许再给钢珠增加动能**——这正是"不同情况调用不同参数"的极端形态：连控制目标都换了。

---

### 维度四：保持区内外 + 启动过渡

同一分段内，还会按**是否处于 ±1 cm 保持区**再叠加一层增益：

| 情形 | 增益 | 常量 |
| --- | :---: | --- |
| 保持区**外**（`\|dx\| > 45 px`）比例/积分增益 | ×1.20 | `MODE_Q5_OUTSIDE_PID_GAIN` |
| 保持区**外**微分增益 | ×1.30 | `MODE_Q5_OUTSIDE_KD_GAIN` |
| 保持区**内**比例/积分增益 | ×1.08 | `MODE_Q5_INSIDE_PID_GAIN` |
| 保持区外微分滤波系数 | 0.30 | `MODE_Q5_OUTSIDE_DERIVATIVE_ALPHA` |

**启动阶段**还额外做三件事（应对车身起步惯性把钢珠推向铰链的问题）：

1. **抗惯性偏置**：`−25°` 斜坡 250 ms → 保持 1600 ms → 1000 ms 内淡出，叠加 `1.8 ×` 速度项，总限幅 `32°`；
2. **调度变量提速**：`effectiveDx = |dx| + |斜率| × 10`，让误差变化快时**提前升档**，而不是等误差变大才换参数；
3. **微分滤波系数时变**：启动期 `0.18`（更灵敏）→ 稳态 `0.40`（更平滑），避免起步时微分噪声被放大。

---

### 维度五：A 点 / B 点方向独立成组

正反向的运动学不对称（摆球机构有铰链侧、重心偏置），因此 A 点与 B 点**各有一套完整参数**：

| 参数族 | A 点（+5 cm） | B 点（−5 cm） |
| --- | --- | --- |
| 驱动偏置 | `+30°` | `−30°` |
| 起步助推 | `+35°` @160 ms | `−35°` @160 ms |
| 制动偏置 | `−28°` | `+28°` |
| 制动 lead | 0.22 s | 0.26 s |
| 制动触发点 | 4.45 cm | −4.35 cm |

---

### 综合增益合成公式

把上面几维乘起来，就是每次 1 ms 中断里真正下发给舵机的增益：

```text
effectiveDx    = |dx| + |d(dx)/dt| × 10              # 偏差 + 变化率 → 提前升档
base           = S1…S6[effectiveDx]                  # 分段增益表
zoneGain       = (|dx| > 45 px) ? 1.20 : 1.08        # 保持区外更有力
zoneKdGain     = (|dx| > 45 px) ? 1.30 : 1.00        # 保持区外更强阻尼

Kp             = base.Kp × 5.0 × zoneGain
Ki             = base.Ki × 5.0 × zoneGain
Kd             = base.Kd × 5.0 × zoneKdGain
OutMax         = min(base.OutMax × 5.0 × zoneGain, 65°)   # 舵机安全上限
OutputDeltaMax = base.OutDelta × 5.0                      # 单帧最大变化，保护舵机
DerivativeAlpha= 0.18（启动） → 0.40 / 0.30（稳态）
u              = Kp·e + Ki·∫e − Kd·v + 启动抗惯性偏置
```

**积分启用条件**（三重门禁，缺一不可）：`|误差| ≤ 1.0 cm` 且 `|速度| ≤ 0.35 cm/s` 且 `dt ∈ [8, 60] ms`；
单 lane 积分输出限幅 `4°`——即**只在"快到位且已慢下来"时才允许积分去啃最后几十毫伏级的稳态误差**。

### 设计经验小结

| 场景 | 策略 | 理由 |
| --- | --- | --- |
| 距离目标很远 | 高 Kp + Ki 归零 + 允许大斜率 | 抢时间，且避免大误差长时间积分导致过冲 |
| 接近目标 | Kd 提高、输出限幅收紧 | 靠微分项"提前收手"，抑制超调 |
| 进入保持区 | 高 Ki 低 Kp、柔和斜率 | 消除稳态误差、不振荡 |
| 车身起步瞬间 | 固定偏置补偿惯性 + 临时降低微分滤波 | 抵消已知的确定性扰动，噪声不放大 |
| 阶段切换 | 状态机驱动，切换时重置相应积分/动力学 | 避免跨阶段"继承"错误的历史状态 |
| 视觉断流 | 80 ms 超时进入 `BALL_STATE_VISION_FAULT` | 失效安全，不盲目继续控制 |

> 同样的"分情况调参"思路也用在**循迹侧**：`curve_params_v5.h` 按线段曲率设 `BASE_STRAIGHT / MID / OUTER` 三档基础 PWM，并在终点前用两段速度调度（`APPROACH1 / APPROACH2`）降低动能以提高停车精度。
